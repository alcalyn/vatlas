# Website

`site/` is a Vite multi-page build in English and French, without a framework. `npm run site:dev`
previews it. `cd site && npm run build` rewrites `docs/` at the repository root.

`docs/` is a build output: gitignored, and built on the production host, since the build bakes the
production `.env` into the HTML.

## Content

- **World map** on the home page, drawn with `jsvectormap`. Covered countries are listed in
  `site/src/js/covered-countries.js`. Countries without a region on the map (Malta, Singapore,
  Northern Ireland) are shown as dots.
- **Country examples**: `data/country-examples.json` holds one real number per country with the
  full API answer. It is generated by `npm run country-examples` (`--only SG` for one country) and
  must not be edited by hand. Country pages end with `<!-- @include partials/country/<lang>.html -->`,
  and `site/examples.js` renders the recorded answer there.
- **Try it box**: samples and their recorded answers live in `site/src/js/demo-data.js`. Other
  numbers are resolved live through the demo endpoints. `test/demoSamples.test.ts` fails when a
  sample stops parsing.

When the API changes, update the site in the same change: `locales/*.json` (the `docs*` groups
hold the API reference), `site/src/_pages/docs.html`, `index.html` and
`site/src/js/demo-data.js`. Nothing fails automatically when they go stale.

## Shared answer rendering

The try-it box, the console's `/lookup` and its audit pages share two files:

- `src/lib/lookupView.ts` decides what an answer means (verdict, grouping, changes between
  plateaus) and returns i18n keys.
- `src/lib/lookupHtml.ts` renders the markup.

Both only import types, so the site bundle does not pull Prisma. Their class names are styled in
`site/src/styles/pages.css` and `src/console/styles.ts`: rename in both.

## Translations

`locales/en.json` and `locales/fr.json` hold every string of the site and the console. The API
always answers in English.

The site resolves `{{t.group.key}}` at build time. The console calls `t('group.key')` per request.

- Keys are at most two levels deep. `test/i18n.test.ts` checks depth, missing keys and
  placeholders.
- `{{name}}` is an i18next placeholder. `{name}` is filled later by browser JavaScript.
- Counted strings use `_one` / `_other` and are called with `{ count }`.
- The plan names "Free" and "Pro" are product names and are not translated.

`npm run i18n -- <code>` prints the strings missing from a locale as a prompt for an LLM, then
reads the translated JSON on stdin (end with Ctrl+D). The paste must contain exactly the requested
keys, otherwise nothing is written. A missing locale file is treated as empty.

To add a language: add `locales/<code>.json` with its `meta` block (`intlLocale`, `flag`), add the
code to `LOCALES` in `src/console/i18n.ts`, and add `site/public/og-<code>.png`. Country pages
(`site/src/_countries/`) and guides (`site/src/_articles/`) are written per language and are not
translations.
